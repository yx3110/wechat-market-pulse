# 本地行情与图片识别

走势图只用于识别标的名称和代码，不读取价格、均线、量价或技术形态。此规则同时用于正文、重点成员卡、标的分析及视觉缓存；旧缓存中的图形判断不会重新进入分析。生活照、消费截图、非财经新闻等非行情图片继续解析，保留生活区和其他话题区。纯文字模型或 rules 仍不能识别图片。

在现有私有配置中添加，不覆盖群、成员和模型设置：

```json
{
  "local_market": {
    "enabled": true,
    "database": "/your/private/data/stock_data.db"
  },
  "market_research": {
    "enabled": false,
    "max_targets": 12
  }
}
```

Windows 路径可写 `C:/private/data/stock_data.db`。`database` 必须是本机已有文件，程序不会创建、下载、更新或修改行情库，也不依赖其他项目的 Python 环境。当前适配 StockTrade 风格的 SQLite 表：

| 表 | 必需字段 |
| --- | --- |
| `securities` | `id, code, name, type, exchange` |
| `daily_quotes` | `security_id, trade_date, open, high, low, close, volume, adj_factor, is_suspend` |

可选 `financial_indicator` 和 `daily_basic` 支持基本面与估值分析。前者使用 `security_id, ann_date, end_date` 及可用的 `or_yoy, netprofit_yoy, dt_netprofit_yoy, grossprofit_margin, netprofit_margin, roe, debt_to_assets, ocfps, eps`；后者使用 `security_id, trade_date, close, pe_ttm, pb`。字段口径对应 Tushare [财务指标](https://tushare.pro/document/2?doc_id=79)、[每日指标](https://tushare.pro/document/2?doc_id=32)，数值仍只读本地库。

财务数据只采用截止日前已公告的报告，只有日期的同日公告保守排除；累计半年/前三季度与单季度区分，ROE不自动年化。毛利率使用 `grossprofit_margin`，不能把金额字段 `gross_margin` 当百分比。最新期缺现金流或扣非时，不拿上期填补；估值必须和本地日线同日且价格一致，负值PE不作为便宜的证据。去年同报告期存在时才计算比率的同比百分点变化。

长图以综合结论开头，再解释关键技术信号、盈利增长与质量、真正相关的消息，以及结论成立/失效条件；不再陈列全部均线、财务字段和公告标题。缺同行或历史分位时不凭单个PE/PB断言高估或低估。完整数据与出处留在依据附录。规则模式提供基于指标的简单条件判断；模型失败时沿用该脚本结果，不伪称深度分析已完成。

当前只接收 `type='A股'`，代码为6位数字，交易所 `SH/SZ/BJ`；日期为 `YYYY-MM-DD`。价格为人民币元，原始 OHLC 为未复权价格；`adj_factor` 必须是对应交易日的真实累计复权因子，不能拿占位数或已复权价格重复计算。成交量必须在同一序列中保持单位一致，仅展示相对前5日均量的比值，不声称已验证绝对单位。建议为 `(security_id, trade_date)` 和 `trade_date` 建索引。

以报告截止时间之前最后一条日线的因子归一，脚本计算前复权 MA5/10/20/60、1/5/20日涨跌、相对量及前20日高低区间。只读取最近80条日线；不足21条、因子缺失、无效数字、OHLC冲突或身份不一致时不展示行情分析卡，也不在长图放“未找到数据”等占位说明。群聊讨论仍可归纳；失败原因留在私有JSON/依据附录。15:05前的A股报告只采用前一日及更早的已结束日线；晚间可使用当日日线。日期距截止日超过7天、末日停牌或该股落后于库内最新交易日，会标为陈旧并省略行情卡。有效日线始终显示真实数据日期。

查询日线前先解析证券身份。完整名称、明确代码和使用者配置的别名先与证券表核对；其他简称由所选模型结合**同群前后文、引用回复、行业和业务**扩展到正式证券名称，再由程序核对代码和交易所。证券表可选的 `industry` 列帮助区分同名公司。模型可以提出字面不相似的惯用昵称所对应的全称，但不能提供未经名录核对的股票代码。市场话题中遗漏的简称也会补充，软件界面名和生活品牌不作为股票提及。

高把握的语境推定会显示“简称 → 正式名称（代码、市场）”和依据，然后继续计算该标的的本地日线、检索该公司的公告；它不会被描述成群友已明确确认。无法区分的名称在私有依据中保留候选和缺少的线索，长图省略没有可用本地行情的分析卡。代码冲突、明确的港股代码不会被推定结果覆盖；本次使用A股时明示A股口径。港美股、指数或商品暂未适配与真正的日线缺失分别记录，不回退到截图或联网行情。

固定简称仍可在私有配置添加 `local_market.aliases`，例如 `{"样本简称": "000001.SZ"}`。默认 `local_market.context_resolution=true`；设为 `false` 可关闭语境模型解析。rules 模式只使用明确名称/代码、已配置别名并列出歧义候选，无需模型或网络。Ollama/LM Studio 等继续使用所选本地模型；本模块不另行调用云端服务。每次解析保留来源编号、判断依据、候选和模型缓存，群昵称与数据库路径不进入解析请求。

每份报告最多分析 `market_research.max_targets` 个标的（1–12），优先正文重点股，再覆盖走势图中识别出的标的及其他市场线索。生活图片中的品牌不会自动变成股票查询。日线数据和群友发言分开显示，HTML附录保留读取的数据与计算口径。群友自己的技术观点仍可归纳，必须注明是其说法。

`local_market.enabled=true` 时，日线始终走本地库。可独立设置 `market_research.enabled=true`，继续使用已有 Yixin 配置检索公告和新闻；这不会启用联网行情回退。rules、`local_only` 模式跳过在线新闻，但本地日线仍可运行，无需模型或API密钥。模型解读失败时保留脚本指标；`rules` 不作复杂观点推断。

读取使用 SQLite 只读连接和一致事务，包含已提交 WAL。缓存签名跟踪数据库、WAL 和配置变化，避免行情更新后复用旧指标。私有数据库路径不会放进模型输入或报告；原始数据、聊天和成员配置不得提交 Git。使用云端分析模型时会按已有配置发送相关指标和选取的聊天证据，使用本地模型时遵循原有离线限制。

编程助手接入时先运行 `demo`、`doctor`，读取实际表结构，抽查字段口径与最新日期，再填写本机私有配置。不要从模拟游戏、回测结果或截图生成的价格表推断真实行情。用户已授权本地数据源后直接完成接入；找不到或存在多个不明确的源时再询问路径。定时任务读取同一配置，不复制实现。
